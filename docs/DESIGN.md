# 设计取舍

> README 只回答"能不能用、怎么装"。这份回答"为什么这么做"，以及"哪些还没做"——给想改它或提 issue 的人。

## 三条写作原则

这个 skill 的规则都过得过三道筛：**能写成数字的写数字，能交给脚本的交给脚本，每条约束都配违约处置**。

- 反例：`粗细适中`、`弯折过多`、`清晰可见` → 正例：2px 线宽、≤2 拐点、对比度 ≥4.5:1
- 只有"文字不得超出线框"会卡死执行者，必须补顺序：换行 → 降字号到下限 → 扩框 → 拆节点，禁止截断
- 自检能测的，就不要写成"请检查"：几何按形状内切算、像素数墨迹、连线逐段采样

## 为什么是"一个入口 + 多个 reference"

- **触发面集中**：五类图用户都说"画个图"，catalog 里五个 skill 会互相抢触发词，一个入口更准
- **内容面分散**：时序图的竖线密集、流程图的禁止交叉，规则放同一页会互相污染
- **共享内核只有一份**：量字、换行、定框、自检对所有类型通用

新类型的 spec 结构**故意只放在 reference 里**：没读就按流程图习惯写 `nodes`，渲染器直接报字段缺失。漂移靠跑不通来拦，不靠"请务必先阅读"。

## 为什么流程图/思维导图还在 SKILL.md 正文

搬进 `references/` 属于**重构**，不是扩展。重构要单独做一次并跑全量回归——不能混在"加类型"里顺手改。

## 两个值得记住的坑

**层名被连线穿过（v1.3）。** 第一反应是给层名加白色底垫——那只是"遮住"，线还在，读者照样能看出错位。真正的解法是把层名**竖排到左侧留白带**，并把"连线不得进入留白带"写成自检项：**结构上消除，而不是视觉上掩盖**。

**退化布线（v1.3）。** 两点同高时，Z 型走法会塌成一条沿框顶边的直线——肉眼看不出来，`连线不穿框` 也不报（正好压在边框上）。解法是两个：生成候选时禁止退化（|Δy| ≤ 8 就不生成），加一条"线段不得落在任何边框上"的检测。
