# ER 图（er）

> 只在 `spec.type` 为 `er` 时读这份。其他三类看 SKILL.md 正文，不需要这份。

## 什么时候用它

讲**"数据怎么存、表之间怎么连"**：实体、字段、主键、一对多 / 多对多。

- ✅ 数据库设计评审、建表前的结构确认
- ✅ 讲清"订单和明细为什么是两张表"
- ❌ 讲业务流程（先用哪张表、按什么顺序写）→ 用流程图
- ❌ 讲服务谁调谁 → 用时序图

## spec 格式

```json
{
  "type": "er",
  "title": "商城订单库",
  "perRow": 3,
  "entities": [
    {
      "id": "user",
      "name": "用户",
      "fields": [
        { "name": "id", "type": "bigint", "pk": true },
        { "name": "nickname", "type": "varchar(32)" },
        { "name": "created_at", "type": "datetime" }
      ]
    },
    {
      "id": "order",
      "name": "订单",
      "row": 0,
      "col": 1,
      "fields": [
        { "name": "id", "type": "bigint", "pk": true },
        { "name": "user_id", "type": "bigint" },
        { "name": "amount", "type": "decimal(10,2)" }
      ]
    }
  ],
  "relations": [
    { "from": "user", "to": "order", "cardinality": "1:N", "label": "下单" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `entities[]` | 实体。`id` 唯一且必填（关系要用它连），`name` 是显示名 |
| `fields[]` | 字段。`name` 必填；`type` 可省（省了只显示字段名）；`pk: true` 显示成 `PK` 前缀 |
| `row` / `col` | 可选，手动定位。**不写就自动按 `perRow` 排**（默认每行 3 个，从左到右、从上到下） |
| `relations[]` | 关系。`from` / `to` 必须是已声明的实体 id |
| `cardinality` | **必须写成 `A:B` 两端形式**，如 `1:N`、`1:1`、`0..1:N`、`N:M`。两端各标一个 |
| `relations[].label` | 关系动词（下单 / 包含 / 被购买），可选但强烈建议 |

## 硬规则

1. **每个实体至少 1 个字段**。空字段表等于没设计。
2. **每个实体应当有主键**（`pk: true`）。没有会给 `[注意]`——不是所有表都需要，但缺了要想清楚。
3. **`cardinality` 必须两端齐全**（`1:N` 而不是 `N`）。只标一端的图会被读错方向。
4. **关系不能指到不存在的实体**（拼错 id 直接报错退出）。
5. **一个实体不超过 8 个字段**。真实表有二十个字段，图里只放**能说明设计的那几个**，其余在正文里说。
6. **同一对实体之间只画一条关系**。两条会被读成两个独立关系（真要两条就合并，或在 `label` 里写清区别）。
7. **实体名用中文业务词，字段名保持数据库原名**（`user_id` 不要翻译成"用户编号"，否则对不上代码）。

## 不要做的事

- ❌ 画完整 DDL（索引、约束、字符集、注释）—— 图里放不下，也没人看
- ❌ 用 `N:M` 却不在图里画出中间表 —— 要么画中间表（推荐，`1:N` + `1:N`），要么在 `label` 里说明
- ❌ 实体超过 8 个 —— 拆成"核心域 + 附属域"两张图
- ❌ 关系线上画箭头（方向由 `cardinality` 的两端表达，箭头会多一层歧义）

## 自检会查什么

结构：实体 ≥ 1、每个实体有字段、字段名非空、缺主键（WARN）、关系 id 存在、`cardinality` 是两端格式、重复关系（WARN）。
几何：实体框不重叠、关系线不穿过无关实体、线端落在框边、关系标签与基数标签不出画布、不压框。
像素：实体名、每个字段、每条关系的基数与动词都真的画上了。

## 常见问题 → 怎么修

| 现象 | 修法 |
|---|---|
| 报错 `er 需要 entities 数组` | 你在画 ER 但写了 `nodes`，去读这份文件 |
| 报错 `第 N 条关系引用了不存在的实体` | `from`/`to` 拼错，或漏声明实体 |
| `关系必须标两端基数` FAIL | 把 `N` 改成 `1:N` |
| 线穿过别的实体 | 调 `row`/`col` 把挡路的实体挪开；排布比流程图更敏感 |
| 实体框太挤 | 减字段（只留关键字段），或把 `perRow` 调小 |
