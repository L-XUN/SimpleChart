# 时序图（sequence）

> 只在 `spec.type` 为 `sequence` 时读这份。流程图 / 思维导图请看 SKILL.md 正文，不需要这份。

## 什么时候用它

讲**"谁在什么时候对谁说了什么"**：消息传递、调用顺序、机制通路、因果链在时间上的展开。

- ✅ 蓝光 → ipRGC → SCN → 松果体 这样的**机制时序**
- ✅ 客户端调服务、服务查库、返回结果这样的**交互顺序**
- ❌ 只有"步骤先后、没有交互对象"的 → 用流程图
- ❌ 有交互但重点是**模块依赖结构**（谁依赖谁，不是谁先调谁）→ 也不该用这个

## spec 格式

```json
{
  "type": "sequence",
  "title": "登录校验",
  "actors": [
    { "id": "u", "name": "用户" },
    { "id": "c", "name": "客户端" },
    { "id": "s", "name": "服务端" }
  ],
  "messages": [
    { "from": "u", "to": "c", "label": "输入账号密码" },
    { "from": "c", "to": "s", "label": "POST /login" },
    { "from": "s", "to": "s", "label": "校验口令哈希" },
    { "from": "s", "to": "c", "label": "200 + token" },
    { "from": "c", "to": "u", "label": "进入首页" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `actors[]` | 从左到右的顺序 = 你写的顺序（最左边是最先发起的一方）。`id` 唯一，`name` 是显示名，可用 `\n` 折行 |
| `messages[]` | **自上而下 = 时间顺序**，数组顺序就是发生顺序，不要插 `at` 之类的时间字段 |
| `messages[].from` / `.to` | 必须是已声明的 `id`；`from === to` 表示自调用 |
| `messages[].label` | **必填**。箭头本身不表达内容，内容全在标签上 |
| `messages[].style` | `sync` 实心箭头（默认）/ `async` 空心箭头 / `return` 虚线空心（返回、反馈） |

## 硬规则

1. **参与者 2～6 个**。超过 6 个 lifeline 会挤成一排面条，拆成两张图。
2. **每条消息必须有标签**。空标签 = 一个没有信息的箭头，自检直接 FAIL。
3. **时间只靠纵向顺序表达**。想强调"同时发生"不要塞进同一条消息，写成两条相邻的消息。
4. **返回/反馈用 `style: "return"`**（虚线），别用实线回箭头——实线回箭头会被读成"又发了一次消息"。
5. **自调用只表达"主体内部发生的变化"**，不要用自调用来代替"发给别人的消息"。
6. **标签写"发生了什么"，不写"箭头类型"**。写"谷氨酸 / PACAP"（递质），不写"发送信号"（空话）。
7. 参与者名字**用领域里的原词**（ipRGC、SCN、松果体），不要翻译成大白话，也不要在图里缩写到看不懂。

## 不要做的事

- ❌ 画激活条（激活期）—— 本版本不支持
- ❌ 画 `alt` / `loop` / `opt` 组合框 —— 不支持；需要分支就拆图或用流程图
- ❌ 给消息加序号（1.、2.）—— 纵向顺序已经表达了，加序号是噪音
- ❌ 用省略号（...）表示"中间还有很多步" —— 拆图，别糊

## 自检会查什么

结构：参与者 ≥ 2、每条消息有标签、没有孤立参与者（只出现不发言，会给 WARN）、重复消息（WARN）、自调用样式正确。
几何：参与者框不重叠、标签不超出画布、标签不压到参与者框。
像素：每个参与者名和每条消息标签都真的画上了（防字体缺失 / 标签丢失）。

## 常见问题 → 怎么修

| 现象 | 修法 |
|---|---|
| 报错 `sequence 需要 actors 数组，至少 2 个` | `actors` 没写或只写了一个 |
| 报错 `第 N 条消息引用了不存在的参与者` | `from`/`to` 拼错，或漏声明了那个 actor |
| `消息必须写内容` FAIL | 给那条消息补 `label` |
| 图太宽放不进去 | 参与者减到 4～5 个，或拆图 |
| 标签压到相邻生命线 | 正常现象（标签底下有背景色挖空）；想更干净就缩短标签 |
